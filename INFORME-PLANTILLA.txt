4. FUNDAMENTO Y ARQUITECTURA
Un Pod es la unidad desplegable que ejecuta el contenedor Grafana.
El Deployment declara el estado deseado y administra los ReplicaSets.
El ReplicaSet procura mantener la cantidad deseada de Pods. En esta practica
se crea automaticamente desde el Deployment; no se define otro ReplicaSet manual.
El Service selecciona Pods con app=grafana y ofrece un punto de acceso estable.
Ruta de acceso: navegador -> proxy de Killercoda -> NodePort 30000 -> Service
puerto 3000 -> Pod de Grafana puerto 3000.
Relacion de control: Deployment grafana -> ReplicaSet grafana-[hash] -> Pods.

5. CONFIGURACION
El manifiesto contiene Namespace, Deployment y Service. El Deployment inicia
con replicas: 1 y selector app=grafana, coincidente con las etiquetas del Pod.
Las probes consultan /api/health para comprobar el inicio y disponibilidad.
El script crea un Secret para la clave administrativa antes de desplegar.
La clave no forma parte del manifiesto ni debe publicarse en el repositorio.
El Service es NodePort: 30000 en el nodo y 3000 en Service/contenedor.
Se usa emptyDir para almacenamiento temporal de cada Pod.

7. USOS DE GRAFANA
- Dashboards de CPU, memoria y red al conectarse a una fuente de metricas.
- Analisis de registros mediante fuentes compatibles, como Loki.
- Visualizacion de tiempos de respuesta y errores de aplicaciones.
- Alertas sobre indicadores operativos.
- Paneles para analizar datos de negocio desde fuentes compatibles.
Este despliegue instala Grafana; no configura automaticamente Prometheus,
Loki ni la captura de metricas de Kubernetes.

8. LIMITACIONES
El laboratorio y sus URLs son temporales. Cada Pod tiene SQLite y emptyDir
independientes. Los dashboards pueden perderse al reemplazar un Pod y no se
comparten entre replicas. Tres Pods demuestran escalado y reconciliacion de
Kubernetes, pero no una configuracion completa de alta disponibilidad de Grafana.
Una instalacion de Grafana con datos compartidos entre replicas requiere una
base MySQL/PostgreSQL compartida y configuracion adicional. El numero de nodos
observado debe documentarse; replicas en un solo nodo no toleran perder ese nodo.
